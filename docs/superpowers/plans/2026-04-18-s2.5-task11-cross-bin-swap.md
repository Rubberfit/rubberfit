## 2. Prerequisite — harden `warm_start::greedy_bottom_left` (Task 10.5)

**Finding (Codex):** today's `greedy_bottom_left` accepts the `_clearance` arg but never uses it, never checks `w <= bin.width`, and only checks `cursor_y + h > bin.height`. A 50×5 item on a 10×100 bin "fits" the probe even though it's 5× too wide. Task 10's FFD uses this as its fit oracle; production inputs that trip the bug would silently mis-route.

**Fix (committed BEFORE cross_bin_swap.rs):**

```rust
pub fn greedy_bottom_left(bin: &Bin, items: &[Part], clearance: f64) -> Result<SeedResult, PackError> {
    let mut placements = Vec::new();
    let mut cursor_y = 0.0f64;
    let mut overflow: u32 = 0;
    for part in items {
        let bbox = rf_geom::application::bbox_of(&part.polygon).map_err(|source| {
            PackError::InvalidPolygon { shape_id: part.shape_id.clone(), source }
        })?;
        let w = bbox.1.x - bbox.0.x;
        let h = bbox.1.y - bbox.0.y;

        // Inflate by 2*clearance for fit-probe correctness. Clearance is a
        // one-sided margin around each item, so two items stacked need
        // 2*clearance between centers AND each item needs `clearance` from
        // the bin boundary. For a conservative seed probe, inflate width
        // and per-instance height by 2*clearance.
        let w_eff = w + 2.0 * clearance;
        let h_eff = h + 2.0 * clearance;

        // Width gate: if the item doesn't fit horizontally under clearance,
        // none of this part's copies fit.
        if w_eff > bin.width {
            overflow += part.quantity;
            continue;
        }

        let mut placed_this_part: u32 = 0;
        for inst in 0..part.quantity {
            // Each copy consumes h_eff = h + 2c of vertical space (the
            // item itself plus its kerf halo on both sides). Total used
            // after k copies = k * h_eff. Fits iff cursor_y + h_eff
            // <= bin.height.
            if cursor_y + h_eff > bin.height {
                break;
            }
            // Emit placement with y shifted up by `clearance` so the
            // inflated bounding box starts at cursor_y.
            placements.push(SeedPlacement {
                // y = cursor_y + clearance, other fields unchanged
                /* unchanged fields */
            });
            cursor_y += h_eff;
            placed_this_part += 1;
        }
        overflow += part.quantity - placed_this_part;
    }
    Ok(SeedResult { placements, overflow })
}
```

**Rationale for clearance application:**

For `k` copies of height `h` stacked vertically with clearance `c`:
- Copy `i` occupies `[y_i, y_i + h]`; its kerf halo is `[y_i - c, y_i + h + c]`.
- Halos must not overlap the bin edges or each other.
- Copy 1's halo starts at `y = 0` (bin bottom, one halo width consumed).
- Copy `k`'s halo ends at `y = k * (h + 2c)` — must be ≤ `bin.height`.

Uniform `h_eff = h + 2c` per copy is a **conservative** approximation: total consumed after `k` copies = `k*h + 2kc`. The exact stack height under jagua's `min_item_separation = c` semantics is `k*h + (k+1)c` (bottom halo `c`, `k-1` inter-item gaps of `c`, top halo `c`). The uniform formula over-counts interior clearance by `(k-1)c` — i.e. probe may false-reject near-packed stacks that the real engine would accept. This is deliberate: the probe is a safety oracle for assignment decisions, and conservative false-rejection is strictly safer than false-acceptance. Downstream GLS will still find the exact arrangement via CDE collision detection.

Documented trade-off:
- False-accept: eliminated (was the original bug).
- False-reject on k ≥ 2 stacks under clearance: acceptable; equivalent to using `c_probe = 2c` instead of `c`. GLS compensates downstream.
- Exact-parity with engine: not this task. If needed later, switch probe to `k*h + (k+1)c` summation.

Width gate uses the same reasoning: `w_eff = w + 2c` must be ≤ `bin.width`.

**Tests (added to warm_start.rs):**
1. `width_gate_rejects_too_wide_items` — 50×5 item on 10×100 bin returns overflow>0 under clearance=0.
2. `clearance_applies_to_vertical_stacking` — two 10×10 items on 10×25 bin with clearance=1.0: (h+2c)=12, 2× stack needs 24 ≤ 25 → fits; clearance=2.0: (h+2c)=14, 2× stack needs 28 > 25 → overflow=1.
3. `clearance_applies_to_bin_boundary` — one 10×5 item on 10×6 bin with clearance=0.3: h_eff=5.6 ≤ 6 → fits (no cursor_y offset); clearance=0.6: h_eff=6.2 > 6 → overflow=1.
4. Existing tests continue to pass (they all use clearance=0 or fit trivially).

**Expected impact on Task 10 FFD:** zero behavioral change on existing test fixtures (all items fit comfortably under clearance=0). Parity tests verified post-fix.

## 3. State representation (Codex-recommended)

Cross-bin operators operate on **copy-count maps**, not `SeedPlacement` vectors. This makes the duplicate-shape-id invariant impossible to violate by construction.

```rust
/// Per-bin shape counts (index into outer Vec is bin index).
type AssignmentState = Vec<HashMap<String, u32>>;

/// Overflow counts, shape_id -> count.
type OverflowState = HashMap<String, u32>;
```

Conversion in/out of `FfdAssignment`:
```rust
fn state_from_assignment(a: &FfdAssignment) -> (AssignmentState, OverflowState) { ... }
fn assignment_from_state(
    s: &AssignmentState,
    o: &OverflowState,
    bins: &[Bin],
    items: &[Part],
    clearance: f64,
) -> Result<FfdAssignment, PackError> { ... }
```

`assignment_from_state` re-runs `greedy_bottom_left` per bin to populate `SeedResult.placements`. This is the materialization step.

**Why counts, not placements:**
- Duplicate shape_id rows are impossible when keyed by `shape_id` in a map.
- Operators become pure state transforms: `swap_two` is 4 integer ops on counts, probe-feasibility is a boolean.
- `SeedPlacement.instance_index` is an OUTPUT concern; counts are the truth.

## 4. Acceptance metric — lexicographic (closed_bins, concentration)

**Gemini proposed:** Sum of squared densities (polarization).
**Codex proposed:** Lexicographic `(closed_bins, concentration)`.
**Reconciled:** Codex's is strictly better — polarization alone can't distinguish "close a bin" from "make one bin denser at another's expense". Closed-bins-first aligns with REMA's business metric (emptying a bin returns it to stock).

```rust
#[derive(Clone, Copy, Debug, PartialEq, PartialOrd)]
struct Score(u32, f64);   // (closed_bins, concentration)

fn score(state: &AssignmentState, bins: &[Bin], item_areas: &HashMap<String, f64>) -> Score {
    let mut closed = 0u32;
    let mut conc = 0.0_f64;
    for (b, counts) in state.iter().enumerate() {
        let used: f64 = counts.iter()
            .map(|(s, q)| item_areas[s] * (*q as f64))
            .sum();
        let stock = bins[b].width * bins[b].height;
        if used == 0.0 {
            closed += 1;
        } else if stock > 0.0 {
            conc += (used * used) / stock;   // concentration term, normalized by bin area
        }
    }
    Score(closed, conc)
}
```

**Acceptance rule:** `accept iff score(after) > score(before)` (strict, lexicographic via `PartialOrd` on tuple). Equal-score candidates NEVER commit. This guarantees termination (no swap-then-swap-back cycle).

**`item_areas` computation:** true polygon area via shoelace (NOT bbox area — bbox is for FFD ordering only; it biases against non-rectangular shapes).

## 5. Operator APIs

All three use the same return type (Codex-recommended idiom):

```rust
type OpResult = Result<Option<FfdAssignment>, PackError>;
```

- `Err(PackError)` — probe failed / bad polygon / invariant violation.
- `Ok(None)` — evaluated, no improving feasible move exists.
- `Ok(Some(new_assignment))` — one strictly improving move committed.

### 5.1 `swap_two`

```rust
pub fn swap_two(
    assignment: &FfdAssignment,
    bin_a_idx: usize,
    bin_b_idx: usize,
    bins: &[Bin],
    items: &[Part],
    clearance: f64,
) -> OpResult;
```

Exhaustively scans unique shape pairs `(s, t)` where `s != t`, `Q[a][s] > 0`, `Q[b][t] > 0`. For each candidate, performs the 4 count mutations (decrement `Q[a][s]`, `Q[b][t]`; increment `Q[a][t]`, `Q[b][s]`) on a shadow state, probes both bins, scores. Returns the single best strictly-improving candidate (first under canonical scan order if tied).

Canonical scan order (determinism spec from Codex):
- Shape keys sorted by `(bbox_area desc, longest_edge desc, shape_id asc)` in both bins.
- Only considers `a < b` by input index (caller must satisfy, or we reject).
- `s == t` rejected immediately (semantic no-op).

### 5.2 `migrate`

```rust
pub fn migrate(
    assignment: &FfdAssignment,
    from_bin_idx: usize,
    to_bin_idx: usize,
    max_items: Option<usize>,
    bins: &[Bin],
    items: &[Part],
    clearance: f64,
) -> OpResult;
```

Transactional. Explodes source bin's copies into units sorted by canonical FFD key `(bbox_area desc, longest_edge desc, shape_id asc, instance_ordinal asc)`. Call this `units[0..L]`.

Scans prefix sizes **in descending order: `k = L, L-1, L-2, ..., 1`** (larger migrations preferred by construction; first feasible improving prefix wins). For each `k`, probes whether receiver bin accepts `{units[0], units[1], ..., units[k-1]}` atomically — if yes AND score strictly improves, commit that prefix. If no improving feasible prefix exists, returns `Ok(None)` (source bin unchanged).

If `max_items = Some(n)`, scan starts at `k = min(L, n)` instead of `L`.

**Failure semantics:** if the receiver probe fails mid-prefix, ALL moves in that prefix roll back. No partial commit. No spill to overflow (that would violate cardinality). Overflow state unchanged by `migrate`.

### 5.3 `unload_lightest_bin`

```rust
pub fn unload_lightest_bin(
    assignment: &FfdAssignment,
    bins: &[Bin],
    items: &[Part],
    clearance: f64,
) -> OpResult;
```

Single-shot + strict-transactional (Codex-locked).

1. Select source bin `src` by `(density asc, used_area asc, input_idx asc)`. If source is already empty, return `Ok(None)`.
2. Explode source's copies into units sorted by FFD key (hardest-first).
3. For each unit in order, test receiver bins in order `(current density desc, priority desc, Remnant-before-Fresh, input_idx asc)`. First receiver that accepts the unit under the shadow state takes it. Keep walking units.
4. If **every** source unit finds a receiver → commit the full unload (src becomes empty, `closed_bins` increments, score improves strictly). Return `Ok(Some(new_assignment))`.
5. If **any** source unit fails to find a receiver → discard the entire shadow state, return `Ok(None)`. No partial commit, no overflow spill.

**Rationale (Codex):** partial unload commit can produce score regressions masked by the lex metric (e.g. concentration drop on receivers without closing src). Strict all-or-nothing keeps the acceptance rule's proof simple and prevents sneaky regressions.

Task 12's coordinator owns the "unload → reselect lightest → unload again" loop; Task 11's operator is one pass.

## 6. Sharp edges / guardrails (debug_asserts)

From Codex's checklist:

1. Before + after every accepted move: `sum placed counts + sum overflow counts == sum requested quantities`.
2. Per-shape: `sum_b Q[b][s] + O[s] == R[s]`.
3. No map retains zero-quantity entries after mutation (strip on write).
4. Every materialized per-bin item list has unique `shape_id` rows + `quantity > 0`.
5. Every touched bin re-probed after materialization returns `overflow == 0`.
6. Every emitted `SeedPlacement.bin_id` matches the owning bin.
7. Overflow rows sorted by `shape_id`; all counts `> 0`.
8. Accepted candidates: `score(after) > score(before)` strict.

Implementation: `debug_assert!` at operator return + after score comparison.
