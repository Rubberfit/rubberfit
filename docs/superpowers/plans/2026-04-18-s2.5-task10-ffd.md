## 2. Guardrails (Codex, both MUST hold)

1. **No duplicate shape_id in per-bin `config.items`.** `search::optimize::replay_seed_into_layout` errors on duplicate `shape_id` (mod.rs:144). When FFD assigns N copies of the same shape to the same bin, they MUST be collapsed into ONE `Part` with `quantity: N` in that bin's config.items.
2. **FFD must seed every copy it routes.** `search::optimize` is cardinality-preserving (separator.rs:390). If FFD claims an item goes to bin X but fails to seed it there, `optimize()` cannot recover — the copy is silently lost.

### 3.3 API

```rust
/// First-Fit-Decreasing bin assignment.
///
/// Sorts items by bbox area descending (with tie-breakers — see §3.4),
/// then for each item tries bins in priority-then-remnant-then-input
/// order (see §3.5), placing the item in the first bin where
/// `warm_start::greedy_bottom_left` can accommodate it alongside
/// previously assigned items for that bin.
pub fn ffd_assign(
    bins: &[Bin],
    items: &[Part],
    clearance: f64,
) -> Result<FfdAssignment, PackError>;
```

### 3.4 Sort key (4-level deterministic)

For each item copy (quantity-1 unit):

1. **Primary:** `bbox.area` descending — standard FFD.
2. **Secondary:** `max(bbox.width, bbox.height)` descending — breaks ties between same-area rectangles of different aspect (e.g. 10×10 vs 20×5 both area=100).
3. **Tertiary:** `shape_id` ascending — stable across same-area same-longest-edge ties.
4. **Quaternary:** instance ordinal (0..quantity) — stable numbering for N copies of the same shape.

bbox computed once per `shape_id` from the original `Part.polygon` (via `rf_geom::application::bbox_of`). Cached in a `HashMap<&str, (f64, f64)>` to avoid N×M recomputation when quantity is high.

### 3.5 Bin ordering

FFD iterates bins in this order:

1. `bin.priority` **descending** (`None` treated as `0` — matches TS `buildPackRequest.ts:32-34` which uses `?? 0`; Gemini sign-off fix, previous draft used `i32::MIN` which would have made `None` bins sort below negative-priority bins, diverging from TS).
2. `bin.kind == BinKind::Remnant` before `BinKind::Fresh` — RF operators want reusable offcuts consumed first.
3. Input order (stable) for ties.

This is the sort order that TypeScript's `buildPackRequest` already applies before calling pack. FFD re-enforces the same ordering in Rust so the engine is robust even if a future caller skips the TS normalization.

### 3.6 Core algorithm

```
fn ffd_assign(bins, items, clearance) -> FfdAssignment {
    if bins.is_empty() { return Err(PackError::NoBins); }
    if items.is_empty() { return Err(PackError::NoItems); }

    // Explode quantities, compute sort keys once per shape.
    let mut units: Vec<AssignmentUnit> = items.iter().flat_map(|part| {
        let bbox = bbox_of(&part.polygon)?;
        let area = (bbox.1.x - bbox.0.x) * (bbox.1.y - bbox.0.y);
        let longest = f64::max(bbox.1.x - bbox.0.x, bbox.1.y - bbox.0.y);
        (0..part.quantity).map(|inst| AssignmentUnit {
            shape_id: part.shape_id.clone(),
            part_ref: part,  // reference for later reconstruction
            bbox_area: area,
            longest_edge: longest,
            instance_ordinal: inst,
        })
    }).collect();

    units.sort_by(|a, b| {
        b.bbox_area.partial_cmp(&a.bbox_area).unwrap_or(Equal)     // area desc
            .then(b.longest_edge.partial_cmp(&a.longest_edge).unwrap_or(Equal))
            .then(a.shape_id.cmp(&b.shape_id))                     // id asc
            .then(a.instance_ordinal.cmp(&b.instance_ordinal))
    });

    let bin_order: Vec<usize> = (0..bins.len())
        .sorted_by(|&i, &j| {
            bins[j].priority.unwrap_or(0).cmp(&bins[i].priority.unwrap_or(0))
                .then(bin_kind_rank(&bins[j].kind).cmp(&bin_kind_rank(&bins[i].kind)))
                .then(i.cmp(&j))
        })
        .collect();

    // Per-bin running assignment: Vec<Part> with cumulative quantity
    // per shape, keyed by shape_id so we never emit duplicate Part rows.
    let mut per_bin_assign: Vec<HashMap<String, u32>> = vec![HashMap::new(); bins.len()];
    let mut overflow: HashMap<String, u32> = HashMap::new();

    'unit: for unit in &units {
        for &bin_idx in &bin_order {
            // Trial assignment: would this unit fit in bin_idx given
            // what's already assigned there?
            let trial = build_trial_items(&per_bin_assign[bin_idx], unit, items);
            let probe = warm_start::greedy_bottom_left(&bins[bin_idx], &trial, clearance)?;
            if probe.overflow == 0 {
                *per_bin_assign[bin_idx].entry(unit.shape_id.clone()).or_insert(0) += 1;
                continue 'unit;
            }
        }
        // No bin fit it.
        *overflow.entry(unit.shape_id.clone()).or_insert(0) += 1;
    }

    // Materialize: re-run warm_start once per bin with its final
    // (collapsed-quantity) Part list. This is the result FFD returns.
    let per_bin: Vec<SeedResult> = (0..bins.len()).map(|i| {
        let final_items = materialize_parts(&per_bin_assign[i], items);
        if final_items.is_empty() {
            Ok(SeedResult { placements: vec![], overflow: 0 })
        } else {
            warm_start::greedy_bottom_left(&bins[i], &final_items, clearance)
        }
    }).collect::<Result<_, _>>()?;

    Ok(FfdAssignment {
        per_bin,
        overflow: overflow.into_iter().collect::<Vec<_>>(),
    })
}
```

Key helpers:
- `build_trial_items(assigned_so_far, new_unit, original_items)` — produces a `Vec<Part>` where the new unit's shape_id has quantity bumped by 1 from `assigned_so_far`; used to probe if the new unit fits.
- `materialize_parts(counts, original_items)` — given a per-shape count map, emits a deduped `Vec<Part>` with `quantity = count` per shape (preserves all other Part fields from the original).

**Codex sign-off fix: both helpers MUST iterate their `HashMap<String, u32>` in a deterministic order** (HashMap default iteration is randomized per-process). Sort the keys by `shape_id` (the same order as in the input `items` slice, or alphabetically — pick one and lock it). Non-determinism here would silently scramble `instance_index` assignment across runs.

**Overflow materialization** (`overflow: Vec<(String, u32)>` in the final `FfdAssignment`) must likewise sort by `shape_id` before emitting.

```rust
let assignment = ffd_assign(&request.bins, &request.items, request.clearance)?;

// Per-bin iteration: optimize each bin's seed in isolation.
for (bin, seed) in request.bins.iter().zip(assignment.per_bin.into_iter()) {
    if seed.placements.is_empty() { continue; }  // FFD routed 0 items here
    let items_for_bin = materialize_parts_for_bin(&seed, &request.items);
    let config = OptimizerConfig {
        bin: bin.clone(),
        items: items_for_bin,
        clearance: request.clearance,
        ..common_cfg
    };
    let result = search::optimize(seed, config)?;
    // ... accumulate ...
}
```

Note: `remaining` is no longer needed — FFD decided once. Overflow is recomputed by pack.rs from `request.items[].quantity - placed_count_per_shape` (matches current pack.rs:100 behaviour).

```rust
//
// First-Fit-Decreasing bin-assignment heuristic.
//
// Fresh code — not a sparrow port. Replaces pack.rs's prior "iterate
// bins in input order with per-bin greedy spillover" with a global
// assignment pass that routes each item to the first bin (in priority
// order) where it still fits alongside previously assigned items.

//      callers going through either TS or direct Rust entry points

//      (replay_seed_into_layout at mod.rs:144 errors on duplicates).
//      When FFD assigns N copies of the same shape to the same bin,
//      quantities are collapsed into a single Part.
//   5. Cardinality preservation: FFD must seed every copy it routes —
//      `search::optimize` cannot recover missing seeds

//   6. Overflow: per-shape `(shape_id, count)` preserved in
//      `FfdAssignment.overflow`. `pack.rs` recomputes the scalar
```

## 4. Tests (TDD, write first)

Six property + regression tests in `ffd.rs`'s `#[cfg(test)] mod tests`. Plus one end-to-end regression in `application::pack::tests`.

### Test 1 — `ffd_beats_naive_on_area_decreasing_case`

Codex Scenario A: `20×20`, `10×10`, `10×5` on bins `20×20` and `20×15`, items ordered small-small-big in the request.

Naive input-order: places `10×10` on bin A, `10×5` on bin A (cumulative 10+5=15), then `20×20` doesn't fit bin A (10+20=30>20) → tries bin B → doesn't fit (20==15? no, 20>15) → overflow.

FFD: sorts to big-medium-small, places `20×20` on bin A, `10×10` on bin B, `10×5` on bin B → no overflow.

Assert: `FfdAssignment.overflow.is_empty()`.

### Test 2 — `tie_break_is_deterministic`

Two shapes with identical area, different `shape_id`. Repeated calls produce identical `per_bin` layouts.

### Test 3 — `single_bin_equivalent_to_warm_start`

1 bin + 3 different-sized items. FFD's `per_bin[0]` should match `warm_start::greedy_bottom_left(bin, items_sorted_by_ffd, clearance)`.

### Test 4 — `total_overflow_preserves_item_accounting`

`sum(overflow) + sum(per_bin[*].placements.len()) == sum(items[*].quantity)`. Items are neither duplicated nor lost.

### Test 5 — `quantity_split_across_bins`

1 shape, quantity=5, bins where 3 fit bin A and 2 fit bin B. After FFD:
- `per_bin[0]` has 3 placements of shape, `Part.quantity == 3` materially.
- `per_bin[1]` has 2 placements.
- No duplicate shape_id within either bin's materialized Part list.

### Test 6 — `bin_priority_respected`

3 bins: priority=5 (Remnant), priority=None (Fresh), priority=10 (Fresh). Expected FFD bin order: priority=10 Fresh (highest), priority=5 Remnant (mid), priority=None Fresh (lowest — `None` is treated as `0`). Remnant-before-Fresh is a tie-breaker on equal priority; here the priorities differ, so it doesn't apply.

A small item that fits anywhere should land in `bins[2]` (priority=10) first.

### Test 7 (integration, in `application::pack::tests`) — `pack_uses_ffd_routing`

Full `pack()` call with 3 items + 2 bins where naive spillover overflows and FFD doesn't. Assert `PackResult.overflow_count == 0`.
