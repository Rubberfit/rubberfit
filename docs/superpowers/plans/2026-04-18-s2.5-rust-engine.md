## Phase b — BPP bin assignment + cross-bin swap (S2.5b)

### Task 10: FFD bin assignment

**Files:** `engine/crates/rema-layout/src/infrastructure/search/assignment/ffd.rs`

Context: today `pack.rs` iterates bins in input order with greedy spillover. We replace this with area-decreasing FFD to get better initial assignment.

Steps:
1. Sort items by bbox area desc (configurable: longest-edge desc, aspect-aware).
2. For each item, try bins in order; place in first-fit using warm-start greedy.
3. Items that don't fit anywhere → overflow.
4. Tests: three items + two bins where naive order overflows but FFD doesn't.
5. Commit: `feat(search): FFD bin-assignment heuristic`

### Task 11: Cross-bin swap operators

**Files:** `engine/crates/rema-layout/src/infrastructure/search/assignment/cross_bin_swap.rs`

Steps:
1. `swap_two(a_bin, b_bin)` — try moving one item from A to B and one from B to A. Keep if global density improves.
2. `migrate(a_bin, b_bin)` — try moving N items from A to B, ignoring A's remainder. Used when closing a bin.
3. `unload_lightest_bin` — try to empty the lowest-density bin into others.
4. Tests: handcrafted scenarios with known-optimal swaps.
5. Commit: `feat(search): cross-bin swap operators (swap/migrate/unload)`

### Task 12: Integrate FFD + swap into `search::optimize`

**Files:** `engine/crates/rema-layout/src/infrastructure/search/mod.rs`, `engine/crates/rema-layout/src/application/pack.rs`

Steps:
1. `search::optimize` now owns all bins, not one at a time. Signature changes:
   - `search::optimize_multi(request: &PackRequest, seeds: &[SeedResult], cfg: &OptimizerConfig) -> Result<Vec<SeedResult>>`
2. `pack.rs` calls `optimize_multi` once per request instead of looping per bin.
3. Per-bin budget internal to `search::optimize_multi` — it decides how to split.
4. Swap operators run every K iterations of the GLS outer loop (K tuned empirically, default 50).
5. Update all parity snapshots.
6. Commit: `feat(search): multi-bin coordination with cross-bin swap (S2.5b complete)`

### Task 13: S2.5b integration tests

**Files:** `engine/crates/rema-layout/tests/multi_bin_integration.rs`

Steps:
1. Test: `multi-sheet-remnant.json` — expect density lift > S2.5a on this multi-bin fixture.
2. Test: `overflow.json` — expect fewer overflow items than S2.5a.
3. Commit: `test(search): multi-bin integration tests`

## Phase c — Progress, cancellation, benchmarks, tuning, tag (S2.5c)

### Task 14: `OptimizerConfig` progress + cancel fields

**Files:**
- `engine/crates/rema-layout/src/infrastructure/search/mod.rs`
- `engine/crates/rema-layout/src/infrastructure/search/progress.rs` (new)
- `engine/crates/rema-layout/src/infrastructure/search/cancel.rs` (new)

Steps:
1. Add `progress_callback: Option<ProgressCallback>` and `cancel_token: Option<Arc<AtomicBool>>`.
2. `ProgressCallback = Arc<dyn Fn(PackProgress) + Send + Sync>`.
3. `PackProgress { iteration, elapsed_ms, best_placed_count, best_density, phase: "explore"|"compress" }`.
4. GLS polls `cancel_token` every 50 iterations. On cancel, return best-so-far cleanly.
5. Progress fires on each new best-so-far improvement — monotonic only (§10.4 of spec).
6. Tests: cancellation returns within 100ms; progress fires at least once per fixture.
7. Commit: `feat(search): progress streaming + cooperative cancellation`

### Task 15: pack-cli streaming protocol

**Files:**
- `engine/crates/pack-cli/src/main.rs`
- `engine/crates/pack-cli/README.md`

Steps:
1. Accept `--stream` flag to emit NDJSON: one progress JSON per new best, then the final PackResult as the last line.
2. Without `--stream`, keep current behavior (single JSON to stdout, newline).
3. Cancellation: if pack-cli's stdin emits a second line containing `{"cancel":true}`, flip the cancel token.
4. Update README with both protocols.
5. Tests: new test `pack-cli-stream.sh` that pipes a fixture + reads progress lines.
6. Commit: `feat(pack-cli): NDJSON progress streaming + stdin cancellation`

### Task 16: RustPackingService wires progress + cancel to TS callers

**Files:**
- `src/infrastructure/services/rustPackingService.ts`
- `tests/packing/rustPackingService.test.ts`

Steps:
1. When `onProgress` is passed, spawn pack-cli with `--stream`, parse NDJSON line-by-line, call `onProgress(packProgress)` for each progress line, resolve the final line as `PackResult`.
2. Accept `AbortSignal` in the pack() options. On abort, write `{"cancel":true}\n` to child stdin.
3. Tests: progress callback invoked ≥1 time; aborting mid-pack rejects with `PackingAbortedError`.
4. Commit: `feat(packing): TS adapter wires progress + AbortSignal to pack-cli stream`
