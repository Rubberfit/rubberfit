```rust
    pub strike_limit:        usize,   // upstream exploration default: 3
    pub n_workers:           usize,   // upstream default: 3 (sparrow config.rs L549-557).
                                       // We keep 3 for Algorithm 10 fidelity; workers run
                                       // sequentially in S2.5a (rayon deferred to Task 18).
                                       // Codex sign-off fix: n_workers=1 would break Alg 10.
    pub sample_config:       SampleConfig,
    pub log_level:           log::Level,
}

#[derive(Debug)]
pub enum SeparateOutcome {
    /// total loss reached zero; snapshot is the resolved layout
    Feasible(LayoutSnapshot),
    /// strike limit reached; snapshot + tracker snapshot are the best
    /// found, to be fed into the next strike / explore phase
    Infeasible {
        snapshot:    LayoutSnapshot,
        ct_snapshot: CTSnapshot,
    },
}

#[derive(Clone, Copy, Debug, Default)]
pub struct SepStats {
    pub total_moves: usize,
    pub total_evals: usize,
}
// + Sum + AddAssign impls (upstream-faithful)

pub trait Terminator        { fn kill(&self) -> bool; }
pub trait SolutionListener  { fn report_improving(&mut self, snapshot: &LayoutSnapshot); }

pub struct NoopTerminator;
impl Terminator for NoopTerminator { fn kill(&self) -> bool { false } }

pub struct NoopListener;
impl SolutionListener for NoopListener { fn report_improving(&mut self, _: &LayoutSnapshot) {} }
```

### 2.2 Methods

**`Separator`:**
- `pub fn new(instance: BPInstance, layout: Layout, mut rng: Xoshiro256PlusPlus, config: SeparatorConfig) -> Self`
  - Builds `CollisionTracker::new(&layout)`, clones workers (each with independent RNG seeded from `rng.random()`).
- `pub fn separate(&mut self, term: &impl Terminator, listener: &mut impl SolutionListener) -> SeparateOutcome`
  - Faithful port of sparrow `separate()` (Algorithm 9), with outcome enum in place of tuple return. Preserves:
    - `min_loss_sol = (self.layout.save(), self.ct.save())` (incumbent)
    - Strike loop bounded by `config.strike_limit`
    - Inner loop bounded by `config.iter_no_imprv_limit`
    - Unweighted-loss improvement check (`loss < min_loss`)
    - `loss < min_loss * 0.98` substantial-improvement reset
    - `initial_strike_loss * 0.98 <= min_loss` strike increment
    - `update_weights` at end of each inner iteration
    - On `loss == 0.0` → `break 'outer` and return `Feasible(cached_snapshot)` (reuse the snapshot just stored into `min_loss_sol.0`; do NOT re-invoke `self.layout.save()`)
  - Checks `term.kill()` at top of outer loop (only — inner loop relies on iter_no_imprv counter).
  - On each new best-so-far: take one `let best_snap = self.layout.save();` into `min_loss_sol.0`, then pass `&best_snap` to `listener.report_improving` — one save per improvement, not two (Gemini sign-off fix).
- `fn move_items_multi(&mut self) -> SepStats`
  - Default path (n_workers >= 2, paper-faithful):
    - Snapshot master `(layout.save(), ct.clone())`.
    - For each worker sequentially:
      - `worker.load(&master_snap, &self.ct)`
      - `stats += worker.move_items()`
    - Pick min-weighted-loss worker, adopt its (layout, ct) into self via `swap` / `clone`.
  - Fast path (n_workers == 1 — only if caller explicitly opts in; NOT the default):
    - Skip the master snapshot; transiently swap self's layout/ct with worker[0], run `move_items`, swap back. Saves one `Layout::save()` + `CollisionTracker::clone()` per iteration.
    - Kept as an escape hatch for single-worker tests and benchmarks; never used in production wiring.
  - Sequential iteration is OK for S2.5a. Codex's invariant: each worker starts from the same master, all but the winner are discarded. We preserve that, with `n_workers=3` (upstream default).
  - Code comment required: "Workers carry independent RNGs seeded from the master in `Separator::new`. Sequential execution is fine here — the independent seeds are what guarantee each worker explores a different item-ordering trajectory. Rayon parallelism returns in Task 18." (Gemini + Codex sign-off fix).
- `fn rollback(&mut self, snapshot: &LayoutSnapshot, ct_snap: Option<&CTSnapshot>)`
  - `self.layout.restore(snapshot)`.
  - `Some(ots)` → `self.ct.restore_but_keep_weights(ots, &self.layout)` (GLS weights preserved across strikes).
  - `None` → `self.ct = CollisionTracker::new(&self.layout)` (fresh; for disruption cases in later tasks).
- ~~`pub fn move_item(&mut self, pk, d_transf) -> PItemKey`~~ — **dropped for Task 5** (Gemini sign-off fix). Upstream `Separator::move_item` was only called by `change_strip_width` (which we delete); `SeparatorWorker::move_item` lives inside the worker. Task 6 can reintroduce on `Separator` if disrupt-two needs a pub entry point.

**`SeparatorWorker`:**
- `pub fn load(&mut self, snapshot: &LayoutSnapshot, ct: &CollisionTracker)` — `self.layout.restore(snapshot); self.ct = ct.clone();`
- `pub fn move_items(&mut self) -> SepStats`
  - Faithful port of sparrow Algorithm 5. Collect colliding items, shuffle with `self.rng`, for each (if still colliding) call `search_placement(&self.layout, item, Some(pk), SeparationEvaluator::new(...), self.sample_config, &mut self.rng)`, accept best sample, call `move_item`. Track `SepStats`.
- `fn move_item(&mut self, pk, d_transf) -> PItemKey` — local `remove_item + place_item + ct.register_item_move`.

### 2.4 File header (deviation block)

```rust
// engine/crates/rf-layout/src/infrastructure/search/gls/separator.rs
//
// Ported from sparrow's `src/optimizer/{separator,worker}.rs` (MIT,
// Copyright 2025 Jeroen Gardeyn, KU Leuven, ejor-snapshot tag c95454e3).
//
// The Separator is the inner loop of the GLS exploration phase. It
// runs a penalty-weighted local search over a single bin's Layout,
// moving colliding items to positions that reduce total collision
// quantification. On success returns `Feasible(LayoutSnapshot)`; on
// strike-limit exhaustion returns `Infeasible { snapshot, tracker }`.
//
// Deviations from upstream:
//   1. Retyped SPP -> BPP by scoping to a single `Layout` instead of
//      SPProblem. Layout exposes its own place/remove/save/restore
//      API, so the Separator never touches BPProblem -- multi-bin
//      coordination is Task 12's concern.
//   2. `change_strip_width` deleted. BPP bins are fixed-size.
//   3. SeparatorWorker inlined in this file (matches tracker.rs /
//      specialized_pipeline.rs convention). Worker vector kept to
//      preserve Algorithm 10 semantics; iterated sequentially (rayon
//      deferred to Task 18).
//   4. `FMT` logging helper replaced with inline `{:.4}` format specs.
//   5. Terminator + SolutionListener introduced as minimal traits with
//      Noop impls. Task 14 replaces the noop impls with real cancel /
//      progress wiring.
//   6. Return signature of `separate()` wrapped in
//      `SeparateOutcome::{ Feasible, Infeasible }` instead of returning
//      `(snapshot, ct_snapshot)` unconditionally -- downstream Task 6
//      explore.rs branches on this distinction.
```

### Test 3 — `separate_infeasible_exits_at_strike_limit`

Two 80×80 squares forced into a 100×100 bin — cannot fit without overlap.

Fixture note: both squares intentionally placed overlapping (e.g. both at (5,5) and (15,15)). `Layout::place_item` does not reject overlapping placements — it only builds the CDE hazard. The overlap is load-bearing for this test; a future reader must NOT "fix" the fixture by spreading them out.

Config: `strike_limit = 2, iter_no_imprv_limit = 20`.

```rust
let outcome = sep.separate(&NoopTerminator, &mut NoopListener);
assert!(matches!(outcome, SeparateOutcome::Infeasible { .. }));
if let SeparateOutcome::Infeasible { snapshot, ct_snapshot: _ } = outcome {
    // snapshot should be the best-ever-seen layout (possibly unchanged
    // if no improvement was ever found)
    assert_eq!(snapshot.placed_items.len(), 2);
}
assert!(tracker_matches_layout(&sep.ct, &sep.layout));
```

### Test 4 — `separate_respects_terminator`

Custom Terminator returns `true` immediately. Overlap input from Test 2. Expect `Infeasible` (not `Feasible`) because separate short-circuits before doing work.

```rust
struct KillImmediately;
impl Terminator for KillImmediately { fn kill(&self) -> bool { true } }
let outcome = sep.separate(&KillImmediately, &mut NoopListener);
assert!(matches!(outcome, SeparateOutcome::Infeasible { .. }));
```

### Test 5 — `tracker_matches_layout_post_separate` (property-style, two variants)

Run separate() under each of the three scenarios above, assert `tracker_matches_layout(&sep.ct, &sep.layout)` holds. This is encoded as an assertion in each of Tests 1-3, so a dedicated test isn't strictly needed; listed for completeness.

### Test 6 — `weighted_loss_monotone_nonincreasing` (Gemini sign-off requirement)

Purpose: guard the `update_weights` port. Upstream has `debug_assert!(w_loss <= w_loss_before * 1.001)` inside the inner loop — if our tracker's `update_weights` is broken, that invariant fails and explore.rs (Task 6) diverges. This test surfaces the break now.

Construct a 3-item overlap (3 × 10×10 squares at (10,10), (12,12), (14,14) in a 100×100 bin). Run `separate()` with `strike_limit = 1, iter_no_imprv_limit = 10`. Instrument via a custom `SolutionListener` that records `ct.get_total_weighted_loss()` each time it fires.

```rust
struct WeightedLossLog(Vec<f32>);
impl SolutionListener for WeightedLossLog {
    fn report_improving(&mut self, _: &LayoutSnapshot) { /* doesn't see ct directly */ }
}
// Alternative: expose a getter on Separator or poll via an inner Fn.
// For now: snapshot get_total_weighted_loss() before/after separate()
// and assert non-increasing — the debug_assert inside tracker.rs is our
// fine-grained guard.
let before = sep.ct.get_total_weighted_loss();
```
