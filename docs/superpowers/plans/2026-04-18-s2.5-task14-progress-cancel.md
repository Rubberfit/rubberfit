## 1. Research lineage

- **Gemini:** APPROVE. Good high-level design but missed three implementation blockers.
- **Codex:** NEEDS-REVISION with three concrete catches:
  1. Cancel check at `kill()` boundary = seconds of latency, not 100ms. Poll must move inside `move_items_multi` + per-worker + per-candidate `search_placement`.
  2. Progress schema `(best_placed_count, best_density)` is degenerate — both effectively invariant after FFD commit. Needs `active_stock_density` or operator-aware metric.
  3. `OptimizerConfig` is below `pack()`; fields there don't reach pack-cli. Need a new `SearchOptions` seam above `optimize_multi()`.

Plus 10 sharp edges: Debug derive break with `Arc<dyn Fn>`, `SolutionListener` doesn't receive bin index, area-density misleading on colliding layouts, `PackError::Timeout` already unused, etc.

This plan adopts Codex's corrections wholesale.

## 2. `SearchOptions` seam (NEW public struct)

`OptimizerConfig` stays internal. Public surface grows a new struct that lives on `PackRequest` or is threaded as a separate arg:

```rust
// domain/request.rs (new)
#[derive(Clone, Default)]
pub struct SearchOptions {
    pub progress_callback: Option<ProgressCallback>,
    pub cancel_token: Option<Arc<AtomicBool>>,
}

pub type ProgressCallback = Arc<dyn Fn(PackProgress) + Send + Sync>;
```

**Not added to `PackRequest` directly** — `PackRequest` derives Serialize/Deserialize, and `Arc<dyn Fn>` isn't serializable. Instead:

```rust
// New pack() signature:
pub fn pack_with_options(request: PackRequest, options: SearchOptions) -> Result<PackResult, PackError>;

// Existing signature delegates:
pub fn pack(request: PackRequest) -> Result<PackResult, PackError> {
    pack_with_options(request, SearchOptions::default())
}
```

Backward-compatible. pack-cli (Task 15) calls `pack_with_options` when `--stream` is active or stdin cancel is detected.

## 3. `PackProgress` frame shape + monotonic filter

```rust
// progress.rs
#[derive(Clone, Debug, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct PackProgress {
    pub iteration: u64,          // emission-sequence counter (NOT GLS n_iter)
    pub elapsed_ms: u64,
    pub best_placed_count: u32,
    pub best_active_stock_density: f64,
    pub phase: String,           // "explore" | "compress" (no "operator" — Codex lock)
}
```

**Critical change from naive spec:** Codex caught that the proposed `best_density` based on `PackResult.overall_density` is invariant after FFD. Replacement:

```text
active_stock_density = sum_placed_area / sum_active_bin_stock_area
where active_bin = any bin with non-empty placements.
```

This DOES change when `unload_lightest_bin` closes a bin (denominator shrinks) — visible operator progress.

Monotonic filter:
```text
emit baseline once (iteration=0, all fields from initial FfdAssignment)
for each committed assignment change in optimize_multi:
    compute (placed_count, active_stock_density)
    if placed_count > last.placed_count
       OR (placed_count == last.placed_count
           AND density > last.density + 1e-6):
        emit
        last = current
```

**Where does filter live:** a new `ProgressEmitter` struct owned by `optimize_multi`, NOT in `SolutionListener`. Reason (Codex): `SolutionListener` gets `&LayoutSnapshot` only — no bin index, no global state. Filter needs global incumbent, only orchestrator has that.

## 4. Cancel token — hot-loop polling

**Codex correction:** `cancel.load(Relaxed)` must be cheap enough to run at the inner iteration boundary. `Arc<AtomicBool>` clone is free; `.load(Relaxed)` is a single memory fence on x86/arm64.

Polling sites (ordered by importance):

| Location | File:line | When |
|---|---|---|
| **Every inner GLS iteration** | `separator.rs:~262` (top of `while n_iter_no_improvement`) | each iter |
| Before each worker | `separator.rs:366` (`move_items_multi` worker loop) | each worker |
| Before each `search_placement` | `sampling.rs:~37` | each candidate |
| Between bins in orchestrator | `multi.rs` before/after `optimize_single` call | each bin |
| Before operator ladder | `multi.rs:195` (`apply_operator_ladder` entry) | each tick |
| Inside `bin_fits` operator probe | `cross_bin_swap.rs:~155` | each probe |

The `CompositeTerminator.kill()` replaces `BasicTerminator.kill()` at the outer strike loop — but the INNER polling bypasses `kill()` entirely and reads `cancel.load` directly for speed.

```rust
// Example of inner-loop polling pattern:
while n_iter_no_improvement < self.config.iter_no_imprv_limit {
    if let Some(c) = &self.cancel_token {
        if c.load(Ordering::Relaxed) { break 'outer; }
    }
    // ... existing body ...
}
```

## 5. `CompositeTerminator` (Codex-recommended)

```rust
// terminator.rs addition
pub struct CompositeTerminator {
    pub deadline: BasicTerminator,
    pub cancel: Option<Arc<AtomicBool>>,
}

impl Terminator for CompositeTerminator {
    fn kill(&self) -> bool {
        self.deadline.kill()
            || self.cancel.as_ref().map_or(false, |c| c.load(Ordering::Relaxed))
    }
}
```

`BasicTerminator` stays unchanged. Keeps concerns separate (Codex rationale: folding cancel into `BasicTerminator` turns it into a kitchen-sink util and makes the deadline path pay cancel-load cost).

## 6. Operator-level cancel (Codex-locked)

**Do NOT return `Ok(None)` on cancel** — indistinguishable from "no improving move," would silently trigger exp back-off in the orchestrator. Use internal 3-state outcome:

```rust
// cross_bin_swap.rs
enum OpOutcome {
    Cancelled,
    NoImprovement,
    Improved(FfdAssignment),
}
```

Public `OpResult = Result<Option<FfdAssignment>, PackError>` stays the same at the API boundary; internal functions use `OpOutcome` and callers distinguish the three. `multi.rs::apply_operator_ladder` propagates `Cancelled` up to `optimize_multi`, which breaks the round loop immediately.

**Critical invariant (Codex sign-off #3):** on `OpOutcome::Cancelled`, `optimize_multi` must short-circuit OUT of the round loop BEFORE mutating `consecutive_noop_operator_ticks`, `operator_gap`, or `rounds_until_next_operator`. Falling through the `None` branch would corrupt back-off state. Test 7 (§10.1) guards this.

**Callback permanent-disable (Codex sign-off #4):** `ProgressEmitter` carries a `callbacks_disabled: bool` flag. Set on first panic caught by `catch_unwind`. Once set, every future emit attempt is a no-op for the rest of the `pack_with_options` call. Test 8 (§10.1) guards this.

## 7. `was_cancelled: bool` on `PackResult` (Codex-locked)

Add to `domain/result.rs`:

```rust
#[derive(Clone, Debug, Serialize)]
pub struct PackResult {
    // ... existing fields ...
    #[serde(default, rename = "wasCancelled")]
    pub was_cancelled: bool,
}
```

`#[serde(default)]` means existing deserializers don't break. `Ok(PackResult { was_cancelled: true, ... })` is the correct semantics for a cooperative cancel — caller gets best-so-far partial result, not an exceptional error.

**Do NOT use `PackError::Cancelled { partial }` or `PackError::Timeout`** — those already exist as errors in `domain/errors.rs:18` but are unused. Mixing "cooperative cancel as Ok" vs "timeout as Err" would produce inconsistent semantics.

---

## 8. Callback safety (Codex-locked)

Every callback invocation wrapped in `catch_unwind(AssertUnwindSafe(...))`. On first panic, log once and mark the emitter as "callbacks-disabled" for the remainder of the call. Rationale: a UI/logging callback shouldn't be able to kill the search thread.

Blocking I/O warning: documented in the callback's rustdoc. "Callback should enqueue or write trivially; do not perform blocking I/O inside."

---

## 9. `OptimizerConfig` Debug derive fix (Codex sharp edge #1)

`OptimizerConfig` currently derives `Debug`. `Arc<dyn Fn>` has no `Debug` impl, so we either:
- Don't put hooks in `OptimizerConfig` at all (the `SearchOptions` seam above makes this natural).
- OR add a manual `impl Debug` that skips the callback.

Chose option 1: keep `OptimizerConfig` clean of callback fields. Hooks live in `SearchOptions`, threaded in parallel to `OptimizerConfig`.

## 10. Tests (Codex test strategy — deterministic + one wall-clock smoke)

### 10.1 Deterministic (in `search/progress.rs` tests)

1. `pre_set_cancel_short_circuits` — cancel token set to true before `pack_with_options`; assert zero work (single baseline frame + immediate return with `was_cancelled: true`). Mirrors existing `KillImmediately` pattern.
2. `cancel_during_operator_returns_pre_operator_assignment` — cancel mid-operator; **compare at the `optimize_multi` / `FfdAssignment` layer**, not public `PackResult` (pack.rs post-processing renumbers `instance_index`, recomputes overflow, adds runtime — observable bit-identity is at the assignment layer only). Codex sign-off §5.
3. `progress_frames_strictly_monotonic` — inject a fixture, capture all frames via a recording callback, assert `(placed_count, density)` tuple strictly increases.
4. `baseline_progress_emits_once` — every fixture produces exactly one frame at `iteration=0`.
5. `no_op_cancel_token_no_premature_exit` — a `None` cancel token doesn't truncate the search.
6. `serialization_matches_camelcase` — `serde_json::to_string(progress)` produces the expected camelCase keys.
7. `operator_cancel_does_not_advance_backoff_state` *(Codex sign-off)* — cancel during `apply_operator_ladder` returns `OpOutcome::Cancelled`; verify `consecutive_noop_operator_ticks`, `operator_gap`, `rounds_until_next_operator` are UNCHANGED (short-circuit before back-off state mutation at `multi.rs:111`).
8. `callback_panic_disables_subsequent_emits_but_search_continues` *(Codex sign-off)* — callback that panics on first invocation; emitter marks `callbacks_disabled=true`; subsequent emit attempts are silently dropped; search completes normally.

### 10.2 Wall-clock smoke test (in `tests/cancel_latency_smoke.rs`)

7. `cancel_returns_within_250ms` — long-budget (5s) infeasible fixture; spawn a helper thread that flips cancel at t=50ms; assert pack return time ≤ 250ms. (100ms is the product SLA; 250ms is the CI-safe assertion per Codex recommendation to absorb loaded-runner jitter.)
