## 2. Divergence resolution — Codex wins on a technical proof

Gemini proposed **Option C**: run `Separator::separate` again with tighter parameters (smaller `strike_limit`, narrower sampling) to polish a feasible layout, with `BppObjective` extended with a bbox fragmentation tiebreak term.

Codex proposed **Option A**: ship a no-op / pass-through, move the 20% budget back to exploration in Task 8.

**Codex wins.** Verified against our merged code:

- `separator.rs:274` — `if loss == 0.0 { break 'outer; }`. Separator exits immediately on feasibility.
- `separator.rs:425` — `worker.move_items()` filters candidates via `self.ct.get_loss(*pk) > 0.0`. On a feasible layout the candidate set is empty; zero moves execute.

So "run Separator again on a feasible layout with tighter params" does literally nothing — it returns `Feasible(current snapshot)` after one iteration of `move_items_multi` with zero moves. Gemini's Option C is dead code against the code we already merged.

Option B (new geometry-compaction heuristic) is out of scope — the plan says "port sparrow's compress.rs"; B is a new feature, not a port.

**Option A locked.** The faithful BPP port of Algorithm 13 is a pass-through wrapper that documents the adaptation and preserves the call site so Task 8 can wire explore → compress uniformly.

## 3. Design (locked)

### 3.1 New module `gls/compress.rs`

```rust
// ~40 LOC: header + pass-through function + 2 tests

pub fn compression_phase(
    _sep:      &mut Separator,
    feasible:  LayoutSnapshot,
    _term:     &impl Terminator,
    _listener: &mut impl SolutionListener,
) -> LayoutSnapshot {
    // Identity. See deviation block for why.
    feasible
}
```

Input: the `LayoutSnapshot` returned from `exploration_phase` when it reached `Feasible(_)`.
Output: the same snapshot, unchanged.

Unused params prefixed `_` to document the intended future surface (when/if BPP compression becomes meaningful). Task 8 will still pass them — keeps the module's public API stable even if we later replace the body with a real algorithm.

### 3.2 Why no `CompressionConfig`

Sparrow's `CompressionConfig` (upstream `config.rs` L40-95) is entirely about strip-shrink schedule (`shrink_range`, `shrink_decay`, `time_limit`) and a dedicated second Separator (`separator_config`). None of those apply to a pass-through. Adding a config struct with no fields is API noise; skip it. If a future task re-implements real compression, it introduces the struct alongside.

### 3.3 Why no `BppObjective` consultation

The Task 1 plan sub-step ("the final accept-reject in compress must consult `BppObjective::is_better`") assumed compress would accept or reject candidates. A pass-through has no accept/reject step — there's nothing to consult. When a future task adds real compression, it revisits this sub-step.

Codex's caveat is load-bearing here: `BppObjective` scores `SearchState` (multi-bin, placed count + overflow). Wrapping a single `Layout` in a dummy `SearchState` with zeroed other bins would mask real improvements because the objective has no per-bin geometry term. Adding such a term is Task 1 / BppObjective surgery, not Task 7.

### 3.4 Task 8 budget change (noted, not in scope)

Task 8's `search::optimize` orchestrator will wire `explore → compress`. With compression a no-op, Task 8 should allocate 100% of `time_budget_ms` to exploration instead of the 80/20 split the parent plan described. Documented as a follow-up for Task 8's plan — not executed here.

// Algorithm 13 is SPP-specific: shrink the strip, re-separate, keep the

// leaves Algorithm 13 with no analogue in a fixed-container setting:
//
//   1. `Separator::separate()` exits immediately when total loss == 0

//      zero moves because `SeparatorWorker::move_items()` filters
//      candidates to items with loss > 0 (separator.rs:425).
//   2. `BppObjective` scores only overflow + placed count; it cannot
//      detect intra-bin geometry improvements. Adding such a term is
//      out of scope (Task 1 / Task 18 territory).
//   3. Upstream's 20% budget slice earns its cost because strip width
//      actually improves SPP density. In BPP the slice would be dead
//      weight. Task 8 will allocate 100% to exploration instead.
//
// Conclusion: the faithful BPP port of Algorithm 13 is identity.
// This module exists to:
//   (a) preserve the call-site uniformity Task 8 expects,
//   (b) document the port decision at the right location,
//   (c) provide a stable seam for a future task to swap in a real
//       BPP compression heuristic (geometric compaction, for example)
//       without touching Task 8's orchestrator.
//
// Deviations from upstream:
//   1. `compression_phase()` returns its input unchanged. Upstream's
//      shrink-retry loop is deleted in full.
//   2. No `CompressionConfig` — upstream's fields drove strip-shrink
//      schedule, which does not apply here.
//   3. `attempt_to_compress` helper deleted.
//   4. Logs the decision at `info` level so operators see compress
//      ran and returned identity (not silent).

### 3.6 Tests (2, identity-focused)

Per Codex §5 must-hold property: test state + RNG stream identity, not density.

```rust
#[test]
fn compress_returns_input_unchanged() {
    // Start from a known feasible snapshot; compression_phase must
    // return byte-identical placements.
    // Codex sign-off note: save the snapshot into a local BEFORE
    // constructing the separator, and before any `&mut sep` call,
    // to avoid a borrow-order footgun in the argument list.
    let (instance, layout) = feasible_fixture();
    let snap_before = layout.save();
    let mut sep = build_separator(instance, layout);
    let snap_after = compression_phase(
        &mut sep, snap_before.clone(),
        &NoopTerminator, &mut NoopListener,
    );
    let before: Vec<(usize, DTransformation)> = snap_before.placed_items
        .values().map(|pi| (pi.item_id, pi.d_transf))
        .sorted_by_key(|(id, _)| *id).collect();
    let after: Vec<(usize, DTransformation)> = snap_after.placed_items
        .values().map(|pi| (pi.item_id, pi.d_transf))
        .sorted_by_key(|(id, _)| *id).collect();
    assert_eq!(before, after, "compression must be identity on feasible input");
}

#[test]
fn compress_does_not_touch_rng() {
    // RNG stream must be unperturbed by the compression phase so
    // (explore, compress) is indistinguishable from (explore, no-op).
    // Same borrow-order note: snapshot the layout before `&mut sep`.
    let (instance, layout) = feasible_fixture();
    let mut sep = build_separator(instance, layout);
    let rng_before = sep.rng.clone();
    let snap = sep.layout.save();
    let _ = compression_phase(
        &mut sep, snap,
        &NoopTerminator, &mut NoopListener,
    );
    // `Xoshiro256PlusPlus` exposes `next_u64()`; compare next draw.
    let mut rng_after = sep.rng.clone();
    let mut rng_reference = rng_before;
    for _ in 0..4 {
        assert_eq!(rng_after.next_u64(), rng_reference.next_u64(),
            "compress must not consume the RNG stream");
    }
}
```
