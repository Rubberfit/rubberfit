## Required changes before implementation

- **§2.1 `Separator.instance` field** — `Separator::new` stores `instance: BPInstance` and also clones it into each `SeparatorWorker`. Fine for S2.5a (n_workers=1), but for n_workers>1 the clones are wasted. Not blocking — flag as TODO in the deviation block, defer until Task 18 when rayon lands.
- **§2.1 `move_item` signature on `Separator`** — plan says "ported for parity" but upstream `move_item` on `Separator` is pub and used by `change_strip_width` (deleted). It is **not** called by `separate` itself; the worker has its own private `move_item`. Either drop `Separator::move_item` entirely (not used by Task 5 or Task 6's disrupt path — disrupt calls into the worker) or mark it `#[allow(dead_code)]` with a note that Task 6 may re-export it. My read: drop it; Task 6 can reintroduce if needed. File:section `docs/superpowers/plans/2026-04-18-s2.5-task5-separator.md:113`.
- **§2.2 `Separator::separate` — `listener.report_improving` call site** — plan says "Calls `listener.report_improving(&self.layout.save())` on each new best-so-far." The snapshot is already computed one line later into `min_loss_sol.0`; compute once and pass by reference to avoid a second `Layout::save()` (which rebuilds a full `CDESnapshot` — nontrivial cost in inner loop). File:section `plan:92-100`.
- **§2.2 `move_items_multi` — sequential workers** — sparrow's Algorithm 10 issues each worker a **distinct random ordering** because the rayon parallel iterator implicitly decorrelates RNG state per thread. Your sequential port must still call `worker.move_items()` against each worker's independent `rng` (seeded from master in `Separator::new`); the plan does preserve this, but add a one-line comment in the code reminding readers the independent RNGs are what makes sequential workers non-degenerate. File:section `plan:102-108`.
- **§2.2 `move_items_multi` — master snapshot cloning cost** — plan snapshots `(layout.save(), ct.clone())` once per outer iteration and re-loads into each worker. With `n_workers=1` this is a wasted save+restore round trip per iteration. Add a fast-path: `if self.workers.len() == 1 { self.workers[0].ct = self.ct.clone(); … adopt back }` — or equivalently, skip the master snapshot when `n_workers == 1`. File:section `plan:102-108`.
- **§3 Test 3 `separate_infeasible_exits_at_strike_limit`** — fixture of two 80×80 squares in 100×100 bin must still be *placeable* (overlapping) at the start; verify the fixture construction uses `Layout::place_item` at positions that guarantee initial overlap (e.g., both at origin), not positions the CDE might reject on placement. `place_item` does not fail on overlap, but be explicit in the fixture helper comment so a future reader doesn't "fix" it. File:section `plan:213-228`.
- **§3 Test 4 `separate_respects_terminator`** — expected outcome `Infeasible` depends on `separate()` checking `term.kill()` at the *top* of the outer loop *before* saving the incumbent. Upstream saves first (line 73) then enters the loop. With `kill()==true`, the function will return the initial snapshot unchanged. The plan correctly specifies "Checks `term.kill()` at top of outer loop (only — inner loop relies on iter_no_imprv counter)" — good. Make sure the test's fixture starts overlapping, otherwise the initial `min_loss == 0.0` would (incorrectly) qualify as feasible under the incumbent-at-return model. The plan's overlap input from Test 2 is correct; keep it explicit. File:section `plan:231-239`.
- **§3 add `ct.get_total_weighted_loss()` monotone-decrease assertion** — the upstream `debug_assert!(w_loss <= w_loss_before * 1.001)` inside the inner loop is a load-bearing invariant. Expose this as a standalone test (feed a 3-item overlap, run 10 iterations, check weighted-loss-trajectory is non-increasing modulo 0.1% tolerance). Currently no test covers it. Nice-to-have if scope-tight, but it's the only test that catches a broken `update_weights` port. File:section `plan:179-245`.
- **§4 step 1 — `unimplemented!()` skeleton** — `Separator::new` cannot be `unimplemented!()` and still let Tests 1-4 compile, because tests call `Separator::new(...)` and read `sep.ct.get_total_loss()` before calling `separate()`. Split step 1 into 1a (types + `new` stub that builds a valid empty state) and 1b (everything else unimpl). File:section `plan:251`.
- **§5.1 missing gate** — add `cargo build --release -p rema-layout` to the local full-build sanity. Release-mode codegen diverges (panic=abort, debug_assert stripped) and the pack-cli binary ultimately runs release-only. A Task 5 separator.rs that compiles debug but trips release LTO is a terrible discovery at Task 8. File:section `plan:272-278`.
